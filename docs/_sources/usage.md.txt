# Command-line Usage

## 🔹 1. Complete Pipeline

**Required:**
- `--mode Complete_Pipeline` → run full analysis from raw FASTQ/FASTA files.  
- `-f, --input <dir|file>...` → one or more paths: a directory containing `.fastq.gz`/`.fasta.gz` files, and/or individual file paths (space-separated), to process a whole folder, a single file, or an explicit subset of files.  
- `-o, --output <dir>` → output directory.  

Use `--nanopore` to enable nanopore mode

```bash
strmie --mode Complete_Pipeline \
       -f /path/to/input_dir \
       -o /path/to/output_dir \
       [other options]
```

## 🔹 2. Index Calculation Only

**Required:**
- `--mode Index_Calculation` → recalculate indices starting from a user-supplied Excel table with allele definitions.
- `-o, --output <dir>` → the **same** output directory used for the original Complete Pipeline run (this mode reuses the `raw_counts` subfolder it created; `-f`/`--input` is not used in this mode).
- `-p, --path <file.xlsx>` → Excel file with predefined alleles (`Sample, CAG_Allele_1, CAG_Allele_2`) for recalculation.

```bash
strmie --mode Index_Calculation \
       -o /path/to/output_dir \
       -p /path/to/CAG_data_for_recalculating_indices.xlsx
```

## Command-line parameters
STRmie-HD provides two main operational modes: Complete_Pipeline and Index_Calculation.

**Main modes**
- `--mode Complete_Pipeline` → run full analysis from raw FASTQ/FASTA files.  
- `--mode Index_Calculation` → recalculate indices starting from a user-supplied Excel table with allele definitions.  

**General options**
- `-f, --input <dir|file>...` → one or more paths: a directory containing `.fastq.gz`/`.fasta.gz` files, and/or individual file paths (space-separated), to process a whole folder, a single file, or an explicit subset of files. Required for `Complete_Pipeline`; not used in `Index_Calculation`.
- `-o, --output <dir>` → output directory (required for both modes). For `Index_Calculation`, this must be the same output directory used for the original `Complete_Pipeline` run.

**Nanopore arguments (used only with `--nanopore`)**
- `--np-max-roi <int>` → max Region Of Interest (ROI) length (default: 300)
- `--np-max-edits <int>` → max edits allowed for both flanks (default: 2)
- `--np-max-edits-left <int>` → override edits for upstream flank (default: 2)
- `--np-max-edits-right <int>` → override edits for downstream flank (default: 3)
- `--np-seed-len <int>` → seed prefilter length (0 disables; suggested 5–7) (default: 0)
- `--np-bestmatch`--np-no-bestmatch` → enable/disable `regex.BESTMATCH` (default: enabled)
- `--np-min-read-len <int>` → minimum read length (default: 50)
- `--np-min-cag-pct <float>` → discard reads if the fraction of in-frame CAG triplets is below this threshold  
         (default: 0.70; set `0` to disable)
- `--np-cag-pct-scope {roi,cag_region}` → region for CAG fraction:
       - `roi` = entire ROI
       - `cag_region` = ROI prefix before the LOI/DOI motif block (default: `cag_region`)
- `--np-allow-caa` → count `CAA` as acceptable alongside `CAG` in the fraction calculation

**Paired-end reads (Complete_Pipeline only)**
- `--merge_paired_end` → detect R1/R2 file pairs in the input (by filename, e.g. `*_R1`/`*_R2` or `*_1`/`*_2`) and merge each pair into a single sample with [PEAR](https://anaconda.org/bioconda/pear) before processing. Files not part of a detected pair are still processed individually. Off by default, each input file is treated as its own sample. Requires the `pear` executable on PATH (`conda install -c bioconda pear`). Per-sample merge statistics are written to `pear_merge_stats.xlsx` in the output directory.
- `--pe_min_overlap <int>` → minimum overlap (bp) required by PEAR to merge a read pair, used only with `--merge_paired_end` (default: `10`).

**Peak detection**

By default (no `--cwt` or `-bc` flag), STRmie-HD calls the two alleles from the two most prominent peaks of the per-sample CAG histogram, where prominence means height above the deepest valley separating a peak from a taller one, not raw read count. Interior peaks are found with SciPy's peak detector, which correctly handles plateaus (common in low-coverage regions, where several adjacent CAG values can tie on read count); the two boundary values of the observed CAG range are checked separately, since SciPy requires lower neighbours on both sides and is therefore blind to a true allele peak sitting at the very edge of the data, such as a large expansion with no reads beyond it. The most prominent candidate is always reported as the first allele; the second allele is the next most prominent candidate that is at least `-i` CAG units away from it, so that stutter and sequencing-noise shoulders next to the same allele are not mistaken for a second, distinct allele, and whose prominence clears a minimum fraction of the first allele's (2.5% for an interior candidate, 30% for a boundary one, since a boundary candidate's one-sided prominence measurement can make a long declining stretch of unrelated low-CAG noise look almost as prominent as a real peak). This algorithm is shared by the default peak calling, the low-coverage rescue path, and the `--cwt` path, so all three report alleles consistently.

- `--cwt` → enable wavelet-based peak detection (`scipy.signal.find_peaks_cwt`) as an alternative to histogram-based detection.  
- `-bc, --cutpoint_based` → call peaks by splitting the histogram at the biological cutpoint (default: 27).  
- `-a <list>` → list of widths (default `[5,6,7,8,9,10]`) used by `find_peaks_cwt` to match expected peak shapes. Because they determine the scale of features considered as peaks — too small misses broad peaks, too large merges or ignores narrow peaks — thus directly impacting sensitivity and specificity in peak calling.
- `-i <int>` → minimum CAG-unit separation between the two allele peaks (default `5`). Local maxima closer than this to the tallest peak are treated as stutter or sequencing noise of the same allele rather than a second, distinct allele; too small a value risks calling noise as a second allele, too large a value risks merging two genuinely close alleles into one.
- `-m <int>` → minimum CAG repeats to consider (default `7`).  

**Indices and thresholds**
- `-c <int>` → cutpoint (default `27`), separates “healthy” vs. “phenotypic” allele range and used for Allele Ratio.  
- `-ti <float>` → relative peak height threshold for **Instability Index** (rAdvanced).  
- `-te <float>` → relative peak height threshold for **Expansion Index** (Advanced).  

**Graphical outputs**
- `--cag_graph` → save histograms of CAG distributions per sample.  
- `--ccg_graph` → save histograms of CCG distributions and warning cases.  

**Index calculation mode (required parameter only for mode Index_Calculation)**
- `-p, --path <file.xlsx>` → Excel file with predefined alleles (`Sample, CAG_Allele_1, CAG_Allele_2`) for recalculation.
